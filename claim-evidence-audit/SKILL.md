# Claim-Evidence Audit — 声称 vs 证据的定量审计

评估一份**声称型文档**（威胁情报报告、券商研报、公司公告、白皮书、调查报道、论文）的可信度：
不是问"它说了什么"，而是问「**它的结论有多少证据托底**」。

## When to Use

- 用户提出一个强主张（"这份报告是耸人听闻""这研报在带节奏""这数据是编的"）→ **用数据检验它，不要附和也不要简单否定**
- 读完一份长报告，要判断哪些结论可以采信、哪些只是推断
- 投资/决策前要评估信源可靠性
- 媒体热点事件中要区分"事实层"与"框架层"
- **观点型内容**（访谈、播客、演讲、方法论、"XX理论"）：用户说"总结一下"时**用户要的通常不只是摘要**。先问自己三件事：这套说法**可证伪吗**、**谁获益**、**它和用户自己的数据对得上吗**。见下方「观点型内容的追加检验」。

**不适用**：用户只要摘要（直接总结）；要提取结构化数据（用 `structured-document-extraction`）。

## 铁律 1 — 数据检验优先于附和

用户提出强主张时，**先量化再表态**。用户说"这些案例是小儿科"，直接附和 = 没价值；用数据做控制变量对比后给出分层裁决 = 有价值。

**裁决必须是分层的**（成立 / 不成立 / 部分成立），并说清**哪一层成立**。实测案例中，用户的直觉同时包含一个不成立的判断（技术分析深度）和一个成立的判断（归因方法论），笼统附和或否定都会误导。

## 铁律 2 — 控制变量后再比较

"中国案例 IoC 少"这个观察，如果不做同类对比就毫无意义（可能所有案例都少）。**先按领域/类型分组，再组内对比**。

```python
# 反面：全量对比 → 可能被案例类型构成污染
# 正面：先分组，再逐组比较
by_domain = defaultdict(lambda: {'A': [], 'B': []})
```

实测：全量看中国案例 IoC 7% vs 其他 52%（差距 8 倍），但分组后发现**常规武器组两边都是 0**——差异集中在监控/网络行动组。

## 铁律 3 — 这把尺先量自己

审计别人的证据强度，前提是自己的输出经得起同一把尺。**给任何基准 / 分级 / 正常范围 / 行业标准时，先问"这个数字有来源吗？"**

三档标注（缺一不可）：

| 档位 | 什么时候用 | 写法 |
|------|-----------|------|
| **【有来源】** | 查到了可引用的出处 | 直接给来源（数据库名、官方标准、研究） |
| **【估计】** | 没有出处，靠经验推断 | **明说"这是估计，没有统计来源"** |
| **【不存在】** | 查过，确实没有这类数据 | 说清"我搜了哪些方向都没有"，给出最接近的可查替代 |

**最严重的错误不是"不知道"，而是把估计包装成表格。** 一个带区间、带档位名（入门/一般/熟练）、带数字的分级表，会让读者默认它来自统计。如果它不是，那就是伪造来源——即使每个数字都"大致合理"。

**被问到"这数据哪来的"时的修正模板**：
```
① 直接承认：这个数字没有来源，是我根据印象合成的。
② 说清边界：我能给的可查的是什么（列出真实来源）。
③ 区分人群：竞技人群 / 运动人群 / 全体人口 —— 三者常差一个数量级。
```

**常见情形：业余人群的分布数据往往根本不存在。** 可查的通常只有三类：
① 竞技成绩数据库（按年龄组）② 官方门槛标准（等级、资格线）③ 赛事成绩分布。
"普通人平均是多少"这类统计，除非有大型健康调查，一般无人系统统计过——**而且权威机构自己可能就说了"难以确定"**（实测：美国大师游泳协会公开表示平均游泳速度难确定，因为"取决于你平均的对象"）。

→ **先查"这类数据存在吗"，再查"数值是多少"。** 找到"权威机构承认数据不存在"本身就是有价值的交付物，比编一个数字诚实得多。

**网上流传的分级表要查它的自述**：很多是教练经验值（页面自标 "approximate coaching references, not official qualification standards"），互相矛盾，因为服务的人群不同。

## 八个检验维度

### 1. 证据来源构成（正则分类计数）

对全文做分类计数，看"证据"到底是什么：

```python
EVIDENCE_TYPES = {
    'A. 自有遥测（我们观察到/账号/交换）': r'\bwe (observed|identified|saw|detected|assess|believe)\b|our (detection|telemetry|analysis)|account[- ]level|exchange',
    'B. 对话/内容原文': r'prompt|conversation|session transcript|dialogue|chat (log|history)',
    'C. 硬取证（IoC/哈希/C2）': r'indicators of compromise|C2\b|SHA-?256|MD5|malware sample|hash',
    'D. 外部公开来源': r'public(ly)? (available|reporting|sources)|open[- ]source|press (report|coverage)',
    'E. 结构/网络分析': r'infrastructure|proxy network|account pool|residential proxy',
    'F. 历史/关联推断': r'previously (reported|observed)|consistent with|associated with|attributed to',
}
```

**判读阈值**：
- **A+B 占比 >60%** → 单方自证（self-attesting）；该文档的结论**无法被外部独立验证**
- **D（外部来源）<10%** → 无交叉验证
- **C（硬取证）<10%** → 没有可复现的技术指标

实测一例：A 44.1% + B 24.1% = 68.2%，C 仅 2.8%，D 4.8% → **评级：薄证据 + 单源**。

### 2. 硬取证比例（有/无 IoC）

统计有可验证指标的案例比例，**组间对比**：

| 组 | 有 IoC | 判读 |
|----|--------|------|
| A 组 | 1/15（7%） | 只有叙述，无可复现指标 |
| B 组 | 14/27（52%） | 有技术取证 |

**IoC 有无是"能不能被第三方验证"的分水岭。**

### 3. 案例类型分布（防止"类型偏见"误判）

把案例按"被用来做什么"分类，看分布是否真有偏向：

```python
MALWARE = r'植入体|implant|malware|exploit|payload|C2|backdoor|loader|0day|phishing|ransomware|credentials'
DOCBASED = r'document|dossier|report|digest|template|draft|summary|analysis document'
```

实测：声称"某组案例都是小儿科"时，分布是 技术攻防型 40% vs 37%（**基本持平**）→ **该主张不成立**。

### 4. 归因链条跨度（最关键的一维）

把归因拆成**观察 → 推断 → 结论**三级，看每级之间的跳跃：

```
观察：「简体中文、中国时区、工作时间、用户用了『抓手』这类词、一个用户自称是政府信息安全官员」
   ↓ 跳跃 1（语义推断）
推断：「符合某国某机构的工作对象与语汇」
   ↓ 跳跃 2（具体化）
结论：「XX部 + XX部 + XX局」
```

**判读**：如果结论的具体程度**超过**证据支持的层级，就是过度归因。
- ✅ 诚实标注：「We **cannot attribute** this activity to a specific entity or actor」
- ✅ 技术支撑才标高置信度：「assessed as one actor (**high confidence**) **through shared infrastructure**」
- ⚠️ 证据弱、结论重：「we **believe** is linked to」+「**User activity suggested**」→ 结论点名三个具体部门

**同时检查内部一致性**：同一份文档里是否有的案例严格自律、有的跨度极大？标准不统一本身就是信号（多人分章、或按叙事需要调整）。

### 5. 标题 vs 正文的落差（耸人听闻的常见位置）

逐条对比标题与正文的断言强度：

```python
titles = [open(f).readline().strip() for f in all_sections]
# 检查标题是否有 hedge 词
HEDGE = r'we believe|suggested|likely|alleged|assessed|cannot attribute|low confidence'
```

实测案例：
- 标题：`Disrupting a China-based operation using Claude to draft a fire control specification`
- 同页正文：`We cannot attribute the activity to a specific entity or actor.`

→ **标题是断言式，正文是推测式。** 这是最硬的证据。

**同时排除误判**：检查"X-based"这类模板是否被**独占地**用于某一方——实测某报告 Russia-based、China-based、Iran-based 都用，所以"专门贴标签"不成立。

### 6. 体裁错配（根本机制）

问：这份文档的**证据标准**和它的**表达形式**是否匹配？

| 证据标准 | 表达形式 | 效果 |
|---------|---------|------|
| 平台内可观测行为（trust & safety） | 威胁情报报告（编号+归因+attack lifecycle+IoC 段） | 读者把"平台滥用"读成"国家威胁" |
| 单季度财务数据 | 长期产业趋势判断 | 读者把"周期"读成"成长" |
| 个别用户投诉 | 产品缺陷普遍性结论 | 读者把"个案"读成"系统性" |

**体裁错配 ≠ 造假**。文档内部可能完全诚实（有 hedge），问题在于形式借用了不该借用的权威。

### 7. 反面检验存在性（有没有试着排除无害解释）

统计"排除其他解释"类措辞（双用途 / 无证据表明 / 也可能是 / benign / we excluded），**按章节分组**：

```python
BENIGN = [r'benign', r'no evidence of', r'we could not (confirm|verify)',
          r'legitimate (use|research)', r'dual[- ]use', r'could also be',
          r'we (excluded|ruled out)', r'alternative explanation']
```

实测（同一份文档内）：

| 章节组 | 反面检验提及 |
|--------|-------------|
| 生物章 | **17 次**（认真区分"研究"与"恶意"） |
| 地缘政治章 | **0-1 次** |

**关键判读**：同一份文档**有能力**做反面检验（生物章做了 17 次），却在某些章节一次不做——**这个不对称本身就是最硬的证据**：前者在做分析（"这是不是危险的双用途研究"），后者在做匹配（"这符合哪个威胁类别的模式"）。

### 8. 可伪造性（归因能不能被任意第三方复制）

问两个问题：

1. **归因依赖什么？** 把它列出来。若依赖的是"行为体自己表现出的特征"——语言、时区、自称身份、用词习惯、支付方式——这套归因**可以被任何人伪造**。
2. **文档是否公布了检测启发式？** 找 "归因信号 / attribution signal / lexicon" 这类表格。

实测案例中，报告在指标表里**明确列出了归因信号词**（"工作抓手""态势感知""线索报"）和地域特征（简体中文 + zh-CN locale + 中国工作时间）。这既是透明度，也是**一张投毒说明书**：

```
想被归因成 A 国 → 用 A 国语言 + A 国时区 + 这些术语 + 在 prompt 里自称官方身份
想避免被归因   → 避开以上全部
```

**推论（这类报告最深的漏洞）**：任何以"用户自称 + 语汇特征"为基础的归因，都**无法区分真实行为体与扮演者**。伪装成本极低，而报告会公开发布——这本身就提供了污染动机。审计时应当把这一点明确写出来，而不只是说"证据弱"。

### 概念补充：框架吸纳（framework absorption）

分类法决定可见性。当一份文档的威胁分类是固定的（国家行为体 / 犯罪 / 黑客…）：

- **框架外的现象不出现** —— 不是"被误判"，而是根本不会进入记录（它没有可归入的类别）
- **框架边缘的现象被吸纳** —— 被压缩进最接近的既有类别，且每一步看起来都"合理"

所以"文档里没有 X"≠"X 不存在"，"文档里有 Y"≠"Y 就是 Y"。审计时要问：**它的分类法覆盖了哪些可能，又遗漏了哪些可能？** 未被覆盖的可能性是沉默的，不会被记录成"排除"。

## 观点型内容的追加检验（访谈 / 播客 / 演讲 / 「XX理论」）

前八个维度是为**结构化声称型文档**（有数据、有章节、有可复现指标）设计的。观点型内容的"证据"是**个人经历 + 类比 + 自造术语**，前八个大半失效。改用下面六条。

### 9. 不可证伪性 —— 把名词换成它的定义

最有效的单一测试：取核心名词，**用它的定义替换它**，再读一遍。

- 换成定义后**只剩通用常识** → 它是**命名法**，不是理论
- 换成定义后**有可检验的预测** → 真理论，继续检验

实测（"薄肌理论"）：定义展开 = 抗阻 + 有氧 + 热量缺口 + 睡眠 = 教科书标准建议。**这个标签的增量信息 = 0；它建立的是个人 IP，不是知识。**

**配套形式检验 —— 正反都成立即零信息量**：取任意成功者 X，X 有标签 →「自律所以成功」；X 无标签 →「有钱但健康要还」。**两种相反输入、同一结论方向 → 理论没有排除任何可能性。**

**并检查反例是否被偷换**：实测把"某人没练该标签"当成"某人反对健身"（实际对方在撸铁跑步）→ **稻草人**。这一步要显式写出来，不要停在"举例如不恰当"。

### 10. 自创精确数字 —— 精度越高越可疑

危险特征（四项全中 = 红牌）：精确到个位数 / **无任何出处** / 自述来源是"**和 AI 研讨后归纳**"（= 用 AI 给数字背书，实质是模型在复述说话人的前提）/ 内部自洽（加起来刚好 100 —— **自洽 ≠ 有效**，这恰恰是最容易被接受的形态）。

**正确裁决粒度：「方向可信，分值不可信」。** 实测中"抗阻训练改善肌肉与代谢""快速减重伴随瘦体重流失"均有真实文献支持，但 25/25/50 的分值是自创。**整段话去掉数字反而更成立。** 不要因为数字假而否定方向，也不要因为方向对而放过数字。

### 11. 动机与利益结构（观点型内容必查）

三问：**谁从"这个说法被相信"中获益** / **两人的真实关系是什么** / **哪一段是产品广告**。

实测：一方卖理论（个人 IP），一方给自家产品做定位叙事；随后暴露出双方存在未披露的商业关系 → 后面数小时"互用彼此的理论语言"就不是巧合。

**判读**：信息交换可能真实存在，但双方都有直接自我服务动机时，整场内容的**独立性归零** —— 不是"一定假"，而是**不能当作第三方证据使用**。

### 12. 第三方反应的立场分布 —— 用接受度做证伪

收集正面/中性/负面**全部**评论（不筛选，尤其不要只找批评来印证自己），再看**每种立场落在哪个层面**：

| 立场 | 落在哪个层面 | 说明什么 |
|---|---|---|
| 正面 | **行为层**（"健康有用""别当舔狗"） | 配方可用 |
| 正面 | **理论层**（"这套有解释力"） | 理论有解释力 |
| 负面 | 动机层（"互相打广告"） | 与 §11 互证 |
| 中性 | 语境层（反讽"不如 XX 理论"） | 该品类标签已通胀 |

**最关键的一条**：**如果所有正面评价都落在行为层、无一条落在理论层 → 这个"理论"没有解释力，只有行为配方。**

**附：反讽即证伪。** 实测有人用同一套句式装游戏术语（"每日委托、500 原石……关注我，了解更多高认知"）照样成立 → **民间版的不可证伪性检验**：句式不承载内容。

### 13. 从具体滑向普适（slide）

比体裁错配更隐蔽：**把某个产品的市场定位，说成某个领域的"终极本质"**。

```
"Agent 经济需要高精度微支付"      ← 站得住（真实痛点）
   ↓ 跳过所有竞争方案（稳定币+传统清算、CBDC、闪电网络、其他 L1…）
"所以 <本家产品> 是答案 / 这就是该领域的终极本质"
```

**检测法：找到那个「所以」。** 若从痛点直接跳到某一家产品、中间没有列举并排除替代方案 → **这是定位广告，不是分析。**

### 14. 孤例证言（anecdote as evidence）

"医生说他是第一个纯粹由 AI 驱动来主动排雷的病人" —— **一次个人经历被包装成方法首创**。检测：这句话是**可核验的统计**，还是**一个人的转述**？后者不构成证据。

### 归档约定

观点型审计的价值**不在观点本身**（多为包装），而在**它可作对照组**。归档到 `research/<topic>-<YYYY-MM>/`：

```
README.md            事实卡（嘉宾/主持/时长/上线时间/结构）+ 结论摘要
原文-<source>.md      逐节全文（要点 + 摘录 + 正文）
第三方反应-<site>.md   正/中/负全收 + 立场分布判读
CRITIQUE-*.md         本文的检验结果
对比-<对象>-<日期>.md   与用户真实数据逐项对照
manifest.json         来源 URL + 抓取时间 + 引用的用户数据文件
```

**manifest 必须记来源 URL、抓取时间、引用的用户数据文件** —— 评估结论会过期，来源与数据引用不会。

### 收尾动作：与用户真实数据对照

用户问"和我现在的状态对比一下"时，**逐项拉真实文件，不用印象**。实测一次对照的产出远大于摘要本身。

**方法**：① 建议逐条 → 用户状态 → 判定（✅更强 / ⚪无关 / 🔴反向命中 / ⚠️误用有害）；② 找**同一件事**上的并列对照（双方都在做的那件事），这通常是最有信息量的一段；③ 收尾只给**一条可立即执行的**，不是一堆建议。

**特别提示**：当嘉宾的建议与用户**已验证的行为模式方向相反**时，要明确写出"**这副药对你有害**"并说明机制。比"可以参考"有价值得多 —— 但**不要**把用户的价值观或人生选择改写成对他的诊断（用户对此会强烈反弹）。

## 附带的修辞手法清单

发现体裁错配后，进一步找这些具体操作：

| 手法 | 表现 |
|------|------|
| **编号体制的权威借用** | 用 `GTG-xxxxx` / `APT-xx` 这类编号，暗示"已被归档的威胁行为体" |
| **归因具体化** | 地理观察（X-based）→ 政治归属 → 具体部门，每级证据支持度下降但表述确定性不降 |
| **数字的武器化** | 同一事实两种表述，耸动的上标题（"1.51 亿次交换"），平实的留在正文（"3,500 个账号"） |
| **hedge 层级剥离** | 分析层 `we believe` → 标题层断言 → 媒体层结论。**每传一手，限定词少一层** |
| **零案例营销** | "我们的最强模型零案例" —— 无法验证的正面声明 |
| **选择性篇幅分配** | 按"叙事价值"而非"实际危害"分配篇幅（如影响力行动占 41% 而技术危害更高的网络行动占 21%） |

## 输出格式

```
## 检验结果

### 先排除误判
[可能被误读为偏见、实际不成立的点 —— 如"X-based 模板非专用"]

### N 组硬数据检验
[每组：指标 / 两组数值 / 比值 / 判读]

### 归因方法解剖
[选最激进与最谨慎的案例各一，拆 观察→推断→结论]

### 修辞机制
[体裁错配 + 具体手法清单]

### 但要公平：文档的真实价值
[哪些部分可信、值多少]

# 最终裁决
| 用户判断 | 裁决 | 依据 |
[逐条给成立/不成立/部分成立 + 证据]

## 修正后的表述
[比用户的直觉更精确的一句话]

## 一句话
[≤40 字]
```

**铁律**：裁决表里**必须**至少有一项是"不成立"或"部分成立"（除非证据真的全面支持）。纯附和 = 审计失败。

## Pitfalls

- **不做控制变量就下结论**：全量对比会被案例构成污染，必须分组。实测中全量差距 8 倍，分组后部分组差距为 0。
- **把"技术描述长"当成"分析可靠"**：描述长度 ≠ 证据强度。一份文档可以写出很细的观察，但归因仍然站不住。
- **忽略文档内部的 hedge**：很多被批评"耸人听闻"的文档，**内部其实有 `we believe` / `low confidence`**。真正的落差在标题层与传播层。**批评要落在准确的位置**——否则指控本身也不严谨。
- **只看一方案例**：检验"是否针对性"前，先看对方阵营的案例是否也被同样处理（标题模板、归因深度、IoC 比例）。
- **把体裁错配说成"造假"**：两者法律与道德含义完全不同。准确的表述是"用 A 标准的证据，套 B 形式的表达"。
- **忘了问"它的证据天花板在哪"**：有些文档的证据强度受**结构性限制**（只能看到自己平台的数据），这不是能力问题。批评应指向"表达形式不受天花板约束"，而不是"分析做得差"。
- **把自己合成的数字当标准**（2026-09 实测踩坑）：给分级表 / 基准 / 正常范围前先自问来源；无来源就声明是估计。用户会追问"这个数据是怎么来的"——回答"是我编的"是正确且必要的，但要立刻补上"我能给的可查的是什么"。这条和上面几条是同一把尺：**审别人的标准，也审自己的输出。**
- **派生数据算完直接发，不做锚点自检**（2026-10-11 实测）：临场写的时区换算函数把**分和时位置写反**，整张表的北京时间全错 —— 而且因为格式精确（`22:00` 这种），**看起来完全可信**。
  **没有来源的数字**和**算错的数字**，对用户的伤害是同一种：他都无法分辨，而且**越精确越有说服力**。
  规则：任何**派生表格**（时区 / 单位 / 百分比 / 差分 / 排序）在呈现前，用 **2–3 个已知锚点**验一遍；能写成断言的就写成断言
  （实测把 `assert bj_hhmm("0 14 * * *") == "22:00"` 钉进脚本，之后每次运行都自动复验）。
  配套反向坑：数据异常时**先排除"输入本身刚变过"**，别急着归因到自己的换算逻辑 —— 实测某任务显示的运行时刻"不对"，真实原因是它的排程**当天刚被改**，上次运行残留的是旧排程时刻，不是时区基准错。
- **用户提供的标识符不匹配时不要强行凑**：用户说"这个字母/型号/编号是 X"而 X 对不上任何已知值时，**直说不匹配**。正确做法是给出推理链（X 与候选 Y 的字母位置吻合度）+ 请用户确认，而不是为了给出答案而断言一个最接近的。
- **只做一次搜索就下"不存在"的结论**：用户说"你再仔细搜索一下"往往是对的。第一轮搜不到 ≠ 不存在，换语言、换关键词、换数据类型（数据库 / 官方标准 / 学术）再搜。但**也别为了交差而编一个** —— 正确的终局可能是"这类数据确实不存在，而且权威机构自己这么说了"。
- **观点型内容套用文档审计的八个维度**（2026-10 实测）：访谈/播客没有 IoC、没有章节结构、没有外部引用，硬套前八个维度只会得出"证据不足"这种**无用结论**。观点型内容要换尺子 —— 用 §9–§14。
- **把"结论错"和"结论不可检验"混为一谈**：前者是事实错误，可被一条反例击倒；后者是**不可证伪**，没有可攻击的具体断言，因此更难反驳也更常见。必须显式写出"**两种相反输入得出同一结论方向**"，而不是笼统说"不够严谨"。
- **看到大量正面评价就以为理论成立**：看正面评价**落在哪个层面**（§12）。全部落在行为层 = 只有配方，没有理论。
- **因为对方身价 / 粉丝量 / 播放量而调高对内容的信任**：这是**幸存者偏差 + 权威转移**。身价与内容质量无关，必须分开评估——审计时要显式声明这条口径，否则裁决会被嘉宾光环污染。
- **负面评价也只用一种声音**：收集第三方反应时**正/中/负全收**。只挑批评来印证自己的结论，和只挑赞美一样是选择偏误。
